## TRAP: regex `</style>` removal over-matched
Removing `Widget.Caramel.QuickDock` (a **self-closing** `<style name="…" parent="" />`) with a
`re.search(r'<style name="X".*?</style>')` pattern ran PAST it to the next real `</style>` and ate
the `TextAppearance.Caramel` base style + its doc comment. Recovered by restoring the block from
`git show HEAD:…`. Lesson: match self-closing styles explicitly (`/>` vs `</style>`).

## MAJOR DISCOVERY (2026-11-14, later session): the "new UI" the user now wants is the one the deletion removed

The user asked (after the deletion merged) to "use Lynxifyy/CaramelClient-UI-pack as the client's
UI". But `main` **before** the deletion (`6b83ec5`) already *was* a port of that pack:

- `ui/compose/caramel/Caramel{Theme,Controls,Glass,Labels,Util}.kt` = the pack's `theme/Theme.kt` +
  `components/*`, value for value (the pack's Compose **Desktop** files are not imported; this is the
  Android port). Consumed by `caramel/launch/CaramelLaunchScreen.kt` (631 lines = the pack's
  `launcher/Home.kt` screen), hosted by `MainActivity.setupCaramelLaunchScreen()`.
- `sweetloader/src/pl/menu/*` (MenuRender/Theme/Widgets/Host/Jni) = "a screen-level port of the UI
  pack's `imgui/src/CaramelMenu.cpp`". Its only consumer was `PresentFrameEffect::OnPresentBoundary`.

Both were deleted by `8a73b8b` (parent PR #184, merged as `cf3c814`) and submodule PR #39 (merged as
`8b69236`). So "use the pack" = **restore that port**, not build new. A plain `git revert 8a73b8b`
restores it and is guaranteed green (the pre-deletion tree passed CI).

**Coverage gap**: only the *launch screen* (Home) + the *in-game menu* were ported. The pack's other
tabs (Mods/Servers/Cosmetics/News/Store) were never ported; those screens were the old View-based
ones (now deleted). The pack's own versions of them carry placeholder data ("Example Network",
"Example Cape", "12,408 playing") which rule 4 (honesty) forbids shipping.

**"Tree background"**: the pack's mod-menu *previews* (`previews/mod_menu/*.png`) show a voxel
tree/forest landscape behind the menu — drawn by `preview/lib.py:game_bg()` as a stand-in for the
game. The real C++ menu draws no trees; it dims the live game (`AddRectFilled(..., IM_COL32(4,9,28,120))`).
So there is nothing tree-shaped to remove in the client — but the backdrop dim could be removed/
made transparent. Needs user confirmation.

**Restore is entangled**: `MainActivity` (2244 lines, the pack launch screen's host) references ~30
legacy UI classes (MsftLoginActivity, SetupWizardActivity, VoiceChatActivity, CustomAlertDialog,
LoadingDialog, DynamicAnim, LaunchIntro, ActivityMainBinding, …). So restoring the pack UI alone is
NOT a clean subset — a full revert brings the legacy View UI back too.
